V3 Events Connector Final Looker Studio Graph Test Suite

Purpose

This file defines the final end-to-end Looker Studio graph suite for Phase 6 of docs/events-v3-phased-plan.md.

These tests verify the user-facing connector behavior after the API-level curl tests pass. The goal is to build a Looker Studio report that covers existing v2 pageview functionality, new v3 pageview compatibility, new v3 event functionality, and final event metadata behavior.

Required data sources

- Data source A: existing v2 connector, pageviews only
- Data source B: new v3 connector configured with Dataset = Pageviews
- Data source C: new v3 connector configured with Dataset = Events

Required report controls

- Date range control covering a known test period with pageviews and events
- Data source control only if useful for comparison pages
- Filter control for pageview dimensions
- Filter control for event_name
- Filter control for one approved event metadata field after metadata filters ship

Recommended test data assumptions

- hostname has pageviews across multiple dates
- hostname has at least two event names, for example signup and checkout
- event rows include at least one approved metadata key, for example plan
- pageviews include multiple paths, countries, device types, browsers, operating systems, and UTM values

Report Page 7 - Negative Looker Studio Checks

Purpose: verify schema boundaries and failure modes in the Looker UI.

Check 7.1 - Event source does not expose pageview-only fields

- Data source: C, v3 events
- Action: open available fields in chart setup
- Expected: path, referrer_hostname, country_code, device_type, browser_name, os_name, utm_source, utm_medium, and utm_campaign are not available unless explicitly added later as event-safe dimensions

Check 7.2 - Pageview source does not expose event-only fields

- Data source: B, v3 pageviews
- Action: open available fields in chart setup
- Expected: event_name and event metadata fields are not available

Check 7.3 - Dataset change is treated as schema-changing

- Data source: B or C
- Action: change Dataset in connector config
- Expected: Looker prompts for field refresh or otherwise makes schema changes visible

Check 7.4 - Unsupported metadata field is unavailable

- Data source: C, v3 events
- Action: search fields for a known unapproved metadata key
- Expected: field is not available

Check 7.5 - Date range control works across v2 and v3 sources

- Data sources: A, B, C
- Action: change the report date range
- Expected: every graph updates and no connector error is shown

Final acceptance checklist

- All v2 pageview graphs still render.
- Equivalent v2 and v3 pageview graphs match for the same hostname, date range, dimensions, metrics, filters, sort, and row limit.
- V3 event scorecards render.
- V3 event date histograms render for hour, day, week, month, and year.
- V3 top event tables and bar charts render.
- V3 event composite tables render.
- V3 event_name filters work from chart filters and Looker controls.
- Approved event metadata dimensions render.
- Approved event metadata filters work.
- Unapproved fields are not exposed in the schema.
- Pageviews and events can appear in one report as separate data sources.
- No graph requires mixing pageview and event fields in one data source.
- No chart shows a connector error for supported combinations.
- Dashboard and elasticsearch-api logs include dataset, query type, row count, and duration for the requests generated by these graphs.
