V3 Events Connector Curl Tests By Phase

Purpose

This file defines API-level curl tests for each implementation phase in docs/events-v3-phased-plan.md.

Run the tests for a phase after that phase is implemented. Re-run all earlier phase tests before moving to the next phase.

Preconditions

- dashboard runs locally and exposes POST /api/looker/query
- elasticsearch-api runs locally and exposes POST /api/looker/query
- the selected hostname has pageview data and custom event data
- the API key has access to the selected hostname
- jq is installed
- metadata phase tests require at least one approved event metadata key in the test data

Shared shell setup

```bash
export DASHBOARD_URL="http://localhost:3000"
export ES_URL="http://localhost:5602"
export API_KEY="sa_api_key_replace_me"
export HOSTNAME="seed.com"
export TIMEZONE="Etc/UTC"
export START_DATE="2026-01-10"
export END_DATE="2026-02-17"
export EVENT_NAME="signup"
export EVENT_NAME_2="checkout"
export EVENT_META_FIELD="event_meta_plan"
```

Dashboard helper pattern

```bash
curl -s -X POST "$DASHBOARD_URL/api/looker/query" \
  -H "Content-Type: application/json" \
  -H "Api-Key: $API_KEY" \
  --data "$BODY" | jq
```

Elasticsearch API helper pattern

```bash

  -H "Content-Type: application/json" \
  --data "$BODY" | jq
```

Test 1.3 - event date histogram interval coverage

```bash
for interval in hour day week month year; do
  BODY=$(cat <<JSON
{
  "dataset": "events",
  "hostname": "$HOSTNAME",
  "timezone": "$TIMEZONE",
  "dateRange": { "start": "$START_DATE", "end": "$END_DATE" },
  "interval": "$interval",
  "dimensions": ["date"],
  "metrics": ["events"],
  "filters": [],
  "orderBy": [{ "field": "date", "direction": "ASC" }],
  "limit": 1000
}
JSON
)

  curl -s -X POST "$DASHBOARD_URL/api/looker/query" \
    -H "Content-Type: application/json" \
    -H "Api-Key: $API_KEY" \
    --data "$BODY" > "/tmp/events-$interval.json"

  case "$interval" in
    hour) regex='^[0-9]{10}$' ;;
    day) regex='^[0-9]{8}$' ;;
    week) regex='^[0-9]{6}$' ;;
    month) regex='^[0-9]{6}$' ;;
    year) regex='^[0-9]{4}$' ;;
  esac

  jq -e --arg regex "$regex" '.schema == [{"name":"date","type":"STRING"},{"name":"events","type":"NUMBER"}] and (.rows | length > 0) and all(.rows[]; (.date | test($regex)) and (.events | type == "number"))' "/tmp/events-$interval.json"
done
```

Expected result: jq exits 0 for every interval.

Phase 6 - Hardening And Release API Smoke Suite

Goal: verify v2 compatibility, v3 pageviews, v3 events, filters, metadata, and rejection paths before Looker Studio graph testing.

Run all Phase 0 through Phase 5 tests first.

Additional Phase 6 checks:

- Repeat every successful dashboard request directly against elasticsearch-api and compare `{ schema, rows }`.
- Repeat pageview requests without `dataset` and with `dataset=pageviews` and compare `{ schema, rows }`.
- Confirm every error case returns HTTP 400, not HTTP 500.
- Confirm response `meta.queryType` is correct for scorecard, date_histogram, terms, and composite.
- Confirm response `meta.rowCount` equals `.rows | length` for every successful response.
- Confirm `meta.truncated` is true when a small `limit` cuts off grouped rows.
- Confirm access checks still happen at the dashboard layer by calling the dashboard endpoint with a bad API key and expecting HTTP 403.
